对着那次对话抽方法

第 02 课只说明了要切开。这节是操作：打开哪场对话、对 agent 说哪段话、抽出后删什么、下次怎么调用。

这节做完你要能亲手走一遍：打开已经满意的那次对话 → 发出提取提示 → 把实例踢出方法 → 存成文件 → 下次只填新实例。现在不要做新的产品设计。

你现在要做的事

不是再写一份产品设计。是对着已经满意的那一次，加一场大约 10%–20% 时长的事后提取。这是 Ousterhout 说的被动投资：设计问题已经暴露（下次还得重写 prompt），现在修。类比，不是原书。原概念见 Working Isn't Good Enough。

  1. 打开已经满意的那次对话

    就在产出那份产品设计的会话里继续。不要新开空白会话从头描述「请帮我总结一个方法论」——上下文不在，agent 只能编一套通用设计课。

    找不到旧对话时：把终稿，加上你还记得的要求，一并贴进新会话，然后立刻做第 2 步。仍然不要让它再设计一版。

  2. 发出提取提示，禁止它再改稿

    复制下面整段，原样发出。它的工作变成：拆方法 / 这一次。不是继续优化那份设计。

    上面这次产品设计已经完成，不要再改那份稿，也不要再出一版新设计。

请把这次工作拆成两部分：
1. 方法：换一个完全不同的产品仍然成立的步骤、产出结构、质量线、禁止事项。
2. 这一次：只属于当前这个产品的事实（名称、用户、约束、视觉、轶事）。

方法只用下面五栏，每栏要短：
- 何时用
- 每次另给的输入
- 每次应得到的产出
- 步骤
- 不要

禁止把产品名、具体用户画像、视觉、个人轶事写进方法。
写完后另列「我拿不准的条目」。

  3. 把混进方法的实例踢掉

    Agent 第一次抽，几乎总会把「这一次」写进方法。你的工作是逐条问：换一个产品，这句话还成立吗？不成立就踢回「每次另给的输入」，或直接删。

  4. 存成你会再次打开的文件

    例如 product-design.md。不要把整次对话导出当方法。只要那五栏。如果你的 agent 支持技能文件，再把这五栏放进技能；先有一份能粘贴的 markdown 就够。

  5. 下次只给方法和新实例

    新的一次产品设计，用下面这种开头。方法不再手写。
