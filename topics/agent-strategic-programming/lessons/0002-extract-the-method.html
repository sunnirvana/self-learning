抽出下次还能用的方法

你已经能判断：产品设计一次做完、稿子满意、下次还得重写 prompt——这是战术式。这节只练最小的战略动作：把「这一次」和「下一次还要的方法」切开。

带走的只有一件事：一次做完之后，立刻花大约 10%–20% 的时间，抽出下次不用重写的那部分。产出满意不是投资；能少写一次 prompt 才是。

你的例子卡在哪

战术式编程的首要目标是让下一项能工作。产品设计稿能用，说明这项已经「能工作」。Ousterhout 的句子正好套上来：仅仅能工作是不够的。见 第 01 课；讲义 Working Isn't Good Enough。

你缺的不是更好的一次答卷，而是系统里还没有一个可调用的「产品设计」方法。知识只活在那次对话里。下次同类工作，等于在没有模块的代码库里把同一段逻辑再手写一遍。

第一次从零写，可以

程序会持续演化：不能一次设计完整个系统，第一次也很难设计对，需求会变。所以第一次对着具体产品从零写 prompt，并不犯规——那时你还不知道方法长什么样。讲义原文：Can't design the whole system at once; Can't get the design right the first time; Requirements change.

犯规的是：你现在已经看见「下次还要重写」，却仍然把抽出方法推到「下一份设计做完之后」。那就是 Ousterhout 说的滑坡——当前截止永远还有下一个。

还在战术式

先把这份稿再打磨完美。方法以后再说。下次仍从空白提示开始。

最小战略动作

稿子已经能用。停下来，切开实例与方法，写下下次只要填实例就能跑的卡片。

切开的办法

类比，不是原书：把一次成功的对话看成刚写完的代码。投资不是把整份对话存档，而是抽一个小模块。

  1. 命名会再次出现的工作：叫「产品设计」，不叫「这一份 App 的设计」。
  2. 逐条切开：下次换一个产品仍为真的，进方法；只属于这个产品的，留在这一次。
  3. 方法只写接口：何时用、每次要提供什么、每次应得到什么结构、按什么步骤、什么不要做。
  4. 整份对话不当方法：试错、跑偏、专属于这个产品的细节，留下只会增加隐晦。

先看一份混在一起的提示

下面不是你的原文，是一份典型的「一次做完」提示。先读，再判断每条该进方法还是只属于这次。

标本 · 一次性提示

  1. 帮我做一份产品设计：校园二手教材。
  2. 先写清要解决谁的什么问题，再谈功能。
  3. 用户是某高校学生，买教材预算五十元。
  4. 每个方案写明不做什么。
  5. 主色用校园绿，Logo 用一本打开的书。
  6. 这个想法来自室友上周买高数书被坑。
  7. 产出包括问题、用户、方案、取舍、下一步验证。

抽出后长这样

方法卡片要短，只放下次仍为真的接口。实例事实每次另给。

产品设计

何时用
要从一个想法做到可讨论的产品方案，而不是立刻写代码或画视觉。
每次另给的输入
想法、已知用户、硬约束、已否决的方向。
每次应得到的产出
问题、用户、方案、取舍（含不做什么）、下一步验证。
步骤
先问题再功能；每个方案写明不做什么；用验证步骤收尾，不把愿景写成计划。
不要
不要把某一次的品牌、配色、个人轶事写进方法；不要把整次对话当方法。

上面是标本抽出来的样子，不是给你用的最终技能。你的产品设计方法，必须从你已经满意的那一次里抽——那里才有你真正用过的步骤和质量线。

把你那次产品设计切开，带回给老师。按这五栏写一版（何时用 / 每次另给的输入 / 每次应得到的产出 / 步骤 / 不要）。不确定的条目标出来。我帮你看：哪些还是「这一次」，哪些已经能当方法。任何一句不清楚的，直接问。

主文献：同一份讲义 Working Isn't Good Enough——尤其是「不能一次设计完」「第一次很难对」和持续 10%–20% 投资。中文对照 第 3 章笔记 里主动投资 / 被动投资两段。
