# 选定 Ousterhout 轨道，目的是迁移到 Agent

用户确认听到的是 John Ousterhout《A Philosophy of Software Design》里的战术式编程 vs 战略式编程，不是 DDD 的战略/战术设计。动机是把这套判断借鉴到大模型使用，尤其是理解 agent。后续课必须同时做到两件事：原概念要准，迁移要显式、可检验。

## Implications

- 工作区用语固定为「战术式编程 / 战略式编程」，不再用「战术性设计 / 战略性设计」。
- 第一节先建立首要目标、增量复杂度、10%–20% 投资，再用一层标明的类比接到 agent。
- 不要从 agent 框架或提示词技巧讲起。
