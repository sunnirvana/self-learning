# Mission: 用战略式编程的眼光使用 Agent

## Why
你已经在用大模型和 agent 做事。如果每次只求「这次能跑」，提示、技能、工具和上下文会像战术式代码一样堆复杂度，agent 会越用越难驾驭。要的不是多记框架名词，而是把 Ousterhout 的判断带进每一次使用：当前优化的是这次任务，还是以后更好改的系统。

## Success looks like
- 能说出战术式编程和战略式编程各自的**首要目标**（Ousterhout 原义）
- 面对一次编码或一次 agent 操作，能判断它留下的是投资还是复杂度
- 能在一次 agent 工作里主动拿出大约 10%–20% 的精力，改善技能、工具或约定，而不是只追加提示
- 能识别「战术式飓风」式的 agent 用法：出活快，系统更难演进

## Constraints
- 用中文授课
- 迁到 agent 时必须标明这是类比，不是 Ousterhout 原书内容
- 先吃透原概念再迁移；不跳过软件设计直接讲 agent 产品

## Out of scope
- DDD 的战略设计 / 战术设计（限界上下文、聚合等）
- Ousterhout 后几章（深度模块、注释、错误处理）——按最近发展区再开
- 提示词技巧大全、具体 agent 产品教程
